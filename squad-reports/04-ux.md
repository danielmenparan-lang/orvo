# ORVO Role 04 — UX Lead Report

**Scope:** `index.html` + `app.js` — landing, auth, post request, builder apply, quotes, chat, admin, dashboard IA  
**Audience:** Product / eng implement tonight  
**Locale:** Microcopy in EN; HE deferred (see § Microcopy)

---

## Verdict

ORVO’s core loop (post → quote → chat → pay) is understandable, but the first viewport fails brand and hero-budget rules, Client and Builder paths share confusing friction (auth gates, dual CTAs, dashboard-as-modal), and high-stakes moments (quotes, Accept & pay, chat rules) lack clarity and trust UI. Fix landing composition + post/quote/chat feedback first; polish IA second.

## 1. Friction map

### Client journey

| Step | Current UX | Friction | Severity |
|------|------------|----------|----------|
| Land | Hero: eyebrow + H1 + lead + **2 primary CTAs** + **2 role cards** (same actions) + inset preview card | Decision overload; duplicate paths; cards in hero | High |
| Start “Post a request” | Unauth → signup modal with intent select (already chosen on landing) | Redundant intent; “Sign in first” if they hit Post while thinking they’re logged in | Med |
| Sign up / sign in | Modal tabs; no password reset; min-6 hint only on signup | Dead-end if lockout; weak trust | Med |
| Post request | Single textarea → title = first 80 chars; category + optional budget | No guided fields (channel, urgency, success criteria); title quality poor | High |
| Dashboard | Full-screen overlay; sidebar “My requests / Messages / Become a builder” | Overlay feels like modal-over-site; “Become a builder” distracts clients | Med |
| Wait for quotes | Request card click → **Chat** view; quotes nested above chat | No dedicated “Quotes received” state; empty = “Waiting for quotes...” buried | High |
| Review quote | Card: name, $, message, “Accept & pay” | No fee disclosure until confirm(); Stripe may be missing | High |
| Pay | `confirm()` dialog; optional Stripe tab | Browser confirm is not a payment UX; fee/total unclear on card | High |
| Chat | Rules as gray hint; block email/phone/WA with toast | Rules feel punitive; no progressive disclosure; no delivery milestones | Med |
| Done | Status badges raw (`open`, `in_progress`, `funded`) | Not human-readable; no “mark complete” / review CTA visible | Med |

**Client happy path drop-offs (predicted):** duplicate hero CTAs → auth wall → thin post form → silent wait → opaque Accept & pay.

### Builder journey

| Step | Current UX | Friction | Severity |
|------|------------|----------|----------|
| Land | “Apply as a builder” + role card + dark section CTA | Same auth wall as client; intent set correctly | Low |
| Sign up | Intent = builder → dashboard → Apply view | Good routing; apply form is long blank fields | Med |
| Apply | Bio 50+, skills, portfolio, LinkedIn, years | Validation via toast only; no progress / what “vetted” means | Med |

| Approved | Nav “Browse jobs”; jobs list open requests | Full description dump; budget free-text; Quote vs Message unclear order | Med |
| Quote | Modal: price + message | Min $1 absurd; no scope checklist; no ETA field | High |
| Message before quote | Allowed; chat rules block outreach | Builders may bounce when demos/links rejected pre-pay | Med |
| My quotes | List → click = chat | No client response indicator; status raw | Med |
| Get paid | Client pays; builder sees status change only | No payout timeline / “funded” explainer in UI | High |

**Builder happy path drop-offs:** apply length → 48h wait with weak reassurance → job cards without structure → quote modal too thin → chat link blocks.

## 2. First viewport / branding issues

Branded landing rules applied against current hero.

### Brand strength — FAIL

- **ORVO** lives mainly in the nav logo (`O` orange + `RVO`). After removing nav, the hero could be any “AI freelancer marketplace”: generic H1 (“Need an AI agent? Meet a builder.”), generic lead, generic preview card.
- Brand is **not** a hero-level signal. Headline overpowers the wordmark.
- Logo treatment is small (22px) vs display H1 (up to 58px).

### Hero budget — FAIL (clutter)

First viewport currently packs:

1. Eyebrow (“Trusted AI agent marketplace”)  
2. Headline  
3. Lead  
4. Two large CTAs  
5. Two role-pick **cards** (duplicate of CTAs)  
6. Inset **preview-card** (not full-bleed)  
7. Trust strip often visible at fold on desktop

**Rules violated:** cards in hero; duplicate CTA groups; no single dominant edge-to-edge visual; flat cream `#F9F9F7` background; Inter + Playfair + terracotta `#FF6B35` ≈ forbidden “cream + serif + terracotta” cluster; inset media card instead of full-bleed hero plane.

### Atmosphere

- Flat background, hairline borders, white cards — SaaS template, not marketplace presence.
- Preview card is a fake job listing, not product/place imagery (WhatsApp thread, kitchen tablet, builder workspace).

### Brand test rewrite (target)

Viewport should read: **ORVO** (large) → one line of promise → one sentence → **one** CTA group (primary Client, text link Builder) → full-bleed visual of an agent in context. No role cards, no fake listing card, no trust strip in the first fold.

## 6. Landing Optimizer (Role 18 overlap)

Conversion-focused tips for the branded landing — implement with §3.1.

1. **One job above the fold:** Client conversion. Builder apply is secondary (text link + `#builders` section).  
2. **Brand-led fold:** Wordmark in hero plane; H1 supports ORVO, does not replace it.  
3. **Social proof below fold:** “Vetted builders · Private chat · Pay via Stripe” under How it works — not competing with the CTA.  
4. **Concrete example as story, not card chrome:** In How it works or a “Example brief” section — restaurant WhatsApp order bot — after the hero.  
5. **CTA continuity:** Hero primary = Post a request; final CTA repeats same label (avoid “Create free account” as equal twin — make it the auth step of Post).  
6. **Reduce choice paralysis:** Remove role-pick cards (duplicate of buttons).  
7. **Intent persistence:** `client-start` / `builder-start` already set signup intent — surface that in auth subtitle; drop redundant select when set.  
8. **Speed to value:** Logged-out Post → signup → **open post modal immediately** (today: often lands on empty My requests).  
9. **Trust without clutter:** One line under primary CTA after fold: “Builders are manually approved before they see jobs.”  
10. **Measure tonight (lightweight):** events on `client-start`, `signup` success, `post` success, `builder-start`, `apply` submit — even `console`/toast counts → later analytics.

## 7. Top 8 UX changes to implement tonight

Ordered by impact × effort for a same-night ship:

1. **Hero declutter + brand-up** — Remove role-pick cards; enlarge ORVO in hero; single primary CTA + text-link builder; drop inset preview from first viewport (move example below fold).  
2. **Post → value path** — After client signup/login with client intent, open **Post request** modal (not empty dashboard).  
3. **Post form quality** — Add explicit Title field; richer placeholder; budget chips or clearer hint; stop using desc.slice(0,80) as title.  
4. **Human status labels** — Map `open` / `in_progress` / `funded` / `completed` / quote statuses to readable EN in cards and badges.  
5. **Accept & pay sheet** — Replace `confirm()` with modal showing amount, fee %, builder payout, then Stripe/continue.  
6. **Client quotes-first detail** — From My requests, show quotes list + Accept before/above chat; empty state “Builders will send quotes here.”  
7. **Chat + mobile composer** — Softer rule microcopy; raise chat usable height on small screens; safe-area toast.  
8. **Strip user-facing ops** — Remove SQL filenames / config email debug from Profile and empty states for non-admins; keep admin-only diagnostics.

**Stretch if time:** quote modal min price + delivery days; client sidebar remove “Become a builder”; mobile nav menu.
